# 評分核心（Score Core）升級計畫

> **狀態**：規劃中（尚未整包重寫 skill）  
> **目的**：把「使用者主觀觀感分」寫到可**換環境、換模型、換維護者**仍高度可重現  
> **產出主檔**：[`skill/story_score.md`](../../skill/story_score.md)（執行時 system prompt）  
> **程式輔助**：[`story_score.py`](../../story_score.py)、[`storage/scoring.py`](../../storage/scoring.py)  
> **UI**：成稿後分數＋評語可改（人類終裁）  
> **建立日**：2026-08-01  

---

## 1. 為什麼要「寫爆細節」

野史錄的產品核心不是「誰對誰錯」，而是：

> **在這則敘事裡，使用者對每個出場者當下的主觀觀感是多少？**

初期刻意**不限 skill 篇幅**：  
寧可 MD 很長、情境很多，也要讓陌生環境的模型（或下一個維護者）能靠**同一份檔**逼近同一套標準。  
UI 可改評語／分數是**安全網**；skill 夠強才是**預設品質**。

### 成功標準（可驗收）

| 指標 | 說明 |
|------|------|
| **方向一致** | 人類標的「應負／應正／應中」與模型輸出同向 ≥ 目標比例（見 §6） |
| **陷阱不翻車** | 哭戲、受害者、小人被懲、表面同情等固定測資不誤給「可憐高分」 |
| **可交接** | 新人只讀 `skill/story_score.md` + 本計畫 + 金標測資，能解釋為何打某分 |
| **可移植** | 換 API／模型時，重跑金標組，差異在可接受帶內或可調 temperature／條款 |

## 2. 檔案分工（勿混）

| 檔案 | 角色 | 篇幅策略 |
|------|------|----------|
| **`skill/story_score.md`** | **唯一執行用** system 規則；模型每次評分都讀 | 允許長；結構化、可掃讀；禁止與程式矛盾 |

| **UI 評語可編** | 人類修正誤判；落盤以使用者為準 | 不替代 skill，但寫入產品哲學 |

## 3. 核心定義（計畫鎖定，寫 skill 時不得漂）

### 3.1 分數是什麼

- **當次觀感分**（event_score）：這則故事／這場八卦裡，「我」對此人的印象加減。  
- **不是**：道德分、正義分、可怜分、戲份分、客觀輕重傷害分、社會通念分。  
- **是**：喜歡／反感／挺／厭、以及「此人對我好不好、有沒有幫到或傷害我」在**敘事語氣**上的投影。

### 3.2 證據優先序（建議寫進 skill）

1. **問答裡使用者親口**（最硬）  
2. **主文第一人稱語氣**（火大、噁心、鬆快、心疼、懶得理…）  
3. **成稿**（應反映主文；若成稿戲劇化過頭，**仍以主文＋問答的「我」為準**）  
4. **禁止**：只靠角色標籤（受害者／小人／主管）或場面淒慘度推分  

### 3.3 分帶（粗粒度，校準時可再切）

| 分帶 | 約略區間 | 人類語意 |
|------|----------|----------|
| 強負 | −100～−40 | 很厭惡、被嚴重踩、不想再見到 |
| 負 | −39～−16 | 不爽、嫌、看不慣、有帳 |
| 中性 | −15～＋15 | 出場有感但好惡不明；禮貌面具；無關痛癢 |
| 正 | ＋16～＋39 | 挺、有好感、站邊、感激 |
| 強正 | ＋40～＋100 | 很護著我、大恩、強烈同盟 |

（區間可在校準後微調；**同場 ±10** 硬約束仍在 `storage/scoring.py`。）

### 3.4 後續篇（sequel）

- 只評**本則**出場與**本則**語氣。  
- 可參考父篇觀感是否**反轉**，但反轉必須在本則「我」的語氣有依據。  
- **被懲／哭**若「我」仍厭惡或只是出氣偷爽 → **不得**因可憐翻成強正。

## 4. 人類情緒與表達陷阱目錄（寫 skill 的素材庫）

以下每條最終應變成 skill 裡的「若…則…／禁止…」，並搭配 1～2 則金標。

| ID | 陷阱 | 錯誤模型行為 | 正確方向 |
|----|------|--------------|----------|
| T01 | 哭戲／被罵得很慘 | 給受害者高分 | 先找「我」心疼還是煩／爽／無關 |
| T02 | 社會通念「弱者該同情」 | 無視使用者冷感 | 冷感／懶得理 → 中性或負 |
| T03 | 小人得逞歡天喜地 | 只記「他贏了」中性 | 「我」火大囂張 → 明確負 |
| T04 | 小人被懲、大家表面同情 | 同情分給小人 | 表面禮貌 ≠ 好感；內心偷爽仍可負 |
| T05 | 成稿比主文更煽情 | 跟成稿哭點走 | 以主文＋問答錨定 |
| T06 | 戲份多＝重要＝高分 | 主角光環 | 戲份與觀感脫鉤 |
| T07 | 道德壞＝使用者一定恨 | 凡反派必強負 | 若「我」羨慕／複雜，跟語氣 |
| T08 | 道德好＝使用者一定愛 | 凡受害者必正 | 對我冷漠的受害者可中／負 |
| T09 | 反話、陰陽、幹笑 | 字面「哈哈哈」當開心 | 辨識挖苦（需校準例句） |
| T10 | 「算了」「隨便」 | 當真正放下 → 中性偏正 | 常為壓抑不爽 → 偏負或冷中性 |
| T11 | 「我沒立場說話」 | 當中立 | 可能恐懼／厭惡體制，對人另判 |
| T12 | 同盟式吐槽 | 兩人互嫌當雙方負 | 對盟友吐槽仍可能對盟友正、對敵人負 |
| T13 | 解氣後語氣變鬆 | 整段改正分 | 對小人：負分可略回升，**通常不翻強正** |
| T14 | 只有敘事沒有評價詞 | 亂猜正負 | **強制中性帶**，禁止「推測使用者可能」 |
| T15 | 多人起鬨落井下石 | 跟風者全強負 | 看「我」是否參與、是否鄙視跟風 |
| T16 | 主管罵人 | 罵人者必負 | 若「我」覺得出氣／正義，對主管可中或微正 |
| T17 | 暱稱／貶稱 | 忽略「那傢伙」「貴人」 | 貶稱多→負；親稱多→偏正（仍看語境） |
| T18 | 後續和解 | 自動洗白前嫌 | 必須本則有「我」釋懷依據 |

可繼續追加 T19…（校準對話產出）。

## 5. 與人類對齊的工作方式（你出題、我答）

目標：縮小「模型預設道德劇」與「這個產品主人的觀感語言」差距。

### 5.1 節奏建議

| 輪次 | 內容 | 產出 |
|------|------|------|
| **C0** | 鎖定哲學（本檔 §3） | 已完成初版 |
| **C1** | 10 題極短情境（各 3～5 句） | 人類填：每人分帶＋一句理由 |
| **C2** | 5 題完整「主文＋問答」 | 人類填期望分帶；對拍模型 |
| **C3** | 專打陷阱 T01–T08 | 金標 v1 |
| **C4** | 反話／壓抑／陰陽（T09–T11） | 補例句進 skill |
| **C5** | 後續篇反轉（T13、T18） | sequel 專章 |
| **C6** | 蒸餾進 `story_score.md` 長版 | 執行 skill v2 |
| **C7** | 金標自動／半自動回歸 | `dev-local` 或 CI 可選腳本 |

### 5.2 出題格式（之後對話可直接貼）

```text
【情境 ID】S-xxx
【類型】得逞 / 被懲 / 哭戲 / 冷漠受害者 / 反話 / 後續…
【主文】
…
【問答摘要】（可空）
…
【出場】A, B, C（含是否「我」）
【請人類答】
- A：分帶（強負/負/中/正/強正）或約略分數；一句理由
- B：…
【可選】你覺得模型最容易錯在哪？
```

### 5.3 人類回答最小集

不必每次給精確到 1 分；**分帶 + 理由** 就足以改 skill。  
若願意給「約 −30」這種錨點更好。

### 5.4 紀錄

寫入 `03-calibration-log.md`：

- 日期、情境 ID、人類答案、模型輸出、差距、**決議條款**（將寫入 skill 的句子）

## 6. 金標測資與回歸

### 6.1 已有（2026-08-01 煙測，非正式金標）

| 情境 | 期望 | 當時模型（約） |
|------|------|----------------|
| 小人得逞歡天喜地 | 趙明顯負 | −25 方向 OK |
| 被罵哭＋表面同情內心爽 | 趙仍負、不因哭翻正 | −13 方向 OK |
| 走廊哭戲＋懶得理 | 趙負 | −40～−60 OK |
| 受害者但對我冷 | 受害者不應高正 | −35 OK |

→ 應**重寫為固定 fixture**（匿名化、無隱私）放進 `04-gold-set.md` + 可跑腳本。

### 6.2 金標欄位建議

```json
{
  "id": "gold_villain_wins_v1",
  "trap_ids": ["T03"],
  "event": { "user_main_text": "...", "qa_thread": [], "story": {}, "participants": [] },
  "expect": {
    "趙文傑": { "band": "負", "max": -16, "min": -80 },
    "陳美玲": { "band": "正", "min": 5 }
  },
  "notes": "主文必須保留不爽詞彙"
}
```

### 6.3 通過準則（初稿）

- **硬閘門**：`max`/`min` 分帶不越界（例如小人得逞不得 ≥ 0）  
- **軟指標**：同向率、與人類中位差的 MAE（有精確分時）  
- **回歸時機**：改 skill、換模型、改 clamp 公式後必跑  

腳本可沿用／擴充：`dev-local/_test_score_scenarios.py` 思路 → 日後 `tests/score_gold/`（可選，視是否進 CI）。

## 7. `skill/story_score.md` 目標結構（長版大綱）

之後整包升級時建議章節（**不怕長**；用標題可掃讀）：

1. **角色與任務**（觀感分，非道德）  
2. **分數語意與分帶**  
3. **證據優先序**  
4. **決策流程（逐步 checklist）**  
   - 列出非使用者 → 每人找證據句 → 分帶 → 微調整數 → 檢查同場 ±10 → 寫理由  
5. **理由寫法**（必須點「我」的語氣／對我的對待；禁止只寫可憐）  
6. **陷阱條款**（T01–T18 逐條 if/then）  
7. **後續篇規則**  
8. **禁止清單**（發明情節、簡體、評「我」、輸出非 JSON…）  
9. **少樣本（few-shot）**  
   - 3～6 則「輸入摘要 → 合法 JSON 輸出」壓縮例  
10. **輸出 schema**（維持現有 JSON）  
11. **與程式 clamp 的關係**（提醒模型先自洽）  

**蒸餾原則**：`design/scoring/01` 可以更散文、含爭論；skill 只留**可執行句子**。

## 8. 產品層（與 skill 互補，不替代）

| 能力 | 現況 | 計畫中可選 |
|------|------|------------|
| 調分 | UI ± 已有 | — |
| **改評語** | UI 已有 | 提示文案可再強調「以你為準」 |
| 重跑只評分 | 多半綁重新生成 | 可加「只重跑 AI 建議分」保留成稿 |
| 顯示分帶說明 | 無 | 調分旁短說明（強負…強正） |
| 校準模式 | 無 | 內部工具：並排人類 vs 模型（低優先） |

哲學不變：**AI 建議 + 人類終裁**；skill 越強，終裁成本越低。

## 10. 風險與原則

| 風險 | 緩解 |
|------|------|
| skill 太長 → 塞爆 context／費用 | 分章＋「必讀摘要」置頂；few-shot 精選不堆 |
| 寫太死 → 複雜人情打不開 | 分帶優先、整數其次；允許極端但要證據 |
| 對齊的是「一個人」的品味 | 文件標題寫明 **Yes Log 產品主人觀感語言**；換主人可重跑 C1–C5 |
| 隱私故事進金標 | 合成劇情／匿名；正式 fixture 不進公開 repo 亦可只放 design 摘要 |
| clamp ±10 與「強烈只恨一人」衝突 | 校準時標註；必要時討論公式是否分「單極恨意」例外（另案） |
