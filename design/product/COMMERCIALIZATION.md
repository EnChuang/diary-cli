# 野史錄 · 商業化／授權整理指南

> **用途**：若要 **App 收費**、或 **廠商買想法／授權／客製**，用本檔當整理清單。  
> **原則**：慢而細；先分清「賣什麼」，再補文件。  
> **注意**：本檔是**方法與目錄**，不是法律意見；合約請找律師。  
> **技術安全點**：`v0.2.1`（C1 後 skill）／`v0.2.0`（Web 主路徑）見根目錄 `MILESTONES.md`。

---

## 1. 先想清楚：你要賣的是哪一種？

| 模式 | 買家要什麼 | 你主要交付 | 風險／備註 |
|------|------------|------------|------------|
| **A. 消費 App 訂閱／買斷** | 好用、隱私、情感價值 | 產品＋持續更新 | 個資、內容敏感、模型成本 |
| **B. 想法／顧問授權** | 概念、流程、評分哲學 | 簡報＋規格＋工作坊 | 易被仿；靠合約與Know-how |
| **C. 軟體授權（源碼／二進位）** | 可跑系統 | repo 精選＋文件＋移交 | 勿交 `.env`／真實 `data/` |
| **D. 白牌／客製** | 改品牌、改規則、部署 | 客製 skill＋UI＋部署 | 報價＝人天＋維護 |
| **E. 資料／模型不算賣點** | — | **不要賣使用者日記內容** | 隱私與信任是產品命 |

多數情況會是 **A 或 B＋D 組合**；「純賣想法」最難定價，要綁**可演示的原型**（你已有）。

---

## 2. 你的「核心資產」是什麼？（廠商真正會問）

### 2.1 產品核心（最值錢、難抄全）

用一句話（已共識）：

> **把八卦寫成野史，並記錄「這一則當下」對他人的主觀觀感分；AI 只做初估依附，人以確認落盤為準。**

可拆成可對外講的模組：

| 模組 | 內容 | 對應本專案 |
|------|------|------------|
| **敘事流水線** | 主文→初稿→出場→追問→成稿→落盤 | `ui/` + `story_*` + `skill/` |
| **觀感分哲學** | 溫度計非仇人榜；每則獨立；可翻轉 | `skill/story_score.md` + `design/scoring/` |
| **人機分工** | AI 建議／人改分改評語／確認才寫庫 | 產品哲學、confirm 流程 |
| **本機／BYOK 隱私敘事** | 金鑰自備、資料在本機 | README／USAGE 安全段 |
| **歷史榜** | 當次分累積，非人格判決 | ledger + board |
| **後續篇** | 同人跨事件可改觀感 | sequel |

### 2.2 相對「商品」、難當獨家的

- 一般 LLM 呼叫、JSON 解析、CRUD 列表  
- 常見 UI 元件（按鈕、主題切換）  
→ 談價時強調 **流程＋評分讀法＋隱私定位**，不要強調「會呼叫 AI」。

### 2.3 絕對不要當賣點交出去的

- 真實 `data/*.jsonl`、使用者事件全文  
- `.env`／API Key  
- 未脱敏的校準私密故事（若含可識別同事）

## 3. 建議整理成的「對外資料夾結構」

不必一次做完；按需從「一頁紙」做到「移交包」。

```text
commercial/                    ← 建議新建（可進 Git 的公開說法；敏感另放）
├── 00-one-pager.md            ← 一頁：問題／解法／差異／現況
├── 01-product-core.md         ← 核心哲學與流程（無實作細節也可）
├── 02-feature-matrix.md       ← 功能表：已做／做一半／不做
├── 03-demo-script.md          ← 3～5 分鐘演示腳本
├── 04-tech-overview.md        ← 技術棧、部署、依賴（無密鑰）
├── 05-ip-and-assets.md        ← 你擁有什麼：repo、文件、品牌
├── 06-pricing-notes.md        ← 訂閱／授權／客製人天（自己填）
├── 07-faq-objections.md       ← 「跟 ChatGPT 差在哪」「隱私」
└── pitch/                     ← 簡報 PDF／圖（可選）
```

本專案**已有原料**對應：

| 對外檔 | 可從哪蒸餾 |
|--------|------------|
| 產品核心 | `README.md`、`USAGE.md` §0、本檔 §2 |
| 評分差異化 | `design/scoring/00-*.md`、`03-calibration-log.md`、`skill/story_score.md`（可給「摘要版」） |
| 功能現況 | `TODO.md`、`dev-local/SESSION.md`、`MILESTONES.md` |
| 演示 | 本機 `run_ui.ps1` + 假資料腳本（勿用真八卦） |
| 技術 | `AGENTS.md` 目錄、requirements |

**給廠商的 skill**：建議另做 **「對外摘要 2～3 頁」**，完整 skill 可列為「授權後交付」或 NDA 後再給。

## 4. 一頁紙（00-one-pager）建議大綱

填空用：

```text
【產品名】野史錄 Yes Log
【一句話】
【誰的痛】（想記職場／人際八卦，但不想公開社群；想有「對人溫度」的私人史）
【怎麼解】（流程 6 步 + 觀感分 + 人確認落盤）
【和 ChatGPT 差在哪】（結構化野史庫、歷史榜、每則獨立觀感、BYOK／本機）
【和日記 App 差在哪】（評的是他人觀感與敘事，不是純心情日記）
【現況】（可演示 Web／CLI；里程碑 v0.2.1）
【商業模式構想】（訂閱／授權／客製＿＿＿）
【下一步你要對方做什麼】（試用／會議／PO）
```

## 5. App 收費時要整理的東西

| 項目 | 說明 |
|------|------|
| 價值主張 | 隱私＋主觀史＋AI 初估，不是通用聊天 |
| 定價假設 | 誰付費？月費／年費／買斷？模型費用誰出（BYOK 可降你成本） |
| 合規 | 個資告知、敏感內容免責、年齡、資料刪除（你已有 wipe） |
| 成本 | ModelArk 呼叫、託管（若將來上雲）、你的時間 |
| 路線圖 | 公開「會做／不做」（例如不做社群廣場） |
| 品牌 | 野史錄／Yes Log、logo（`design/brand/`） |

## 6. 廠商「買想法」時要整理的東西

廠商常買的是 **可複製的方法論 + 可跑證明**，不是一句 slogan。

建議包裹：

1. **問題定義**（為何現有筆記／ChatGPT 不夠）  
2. **方法論**（流水線、觀感分公理、人機分工）— 來自 scoring 深度校準  
3. **可演示原型**（你的 diary-cli Web）  
4. **校準方法**（如何用主人樣本把 AI 拉回主觀）— 這是 Know-how  
5. **移交清單**（源碼範圍、文件、訓練／校準紀錄脱敏版）  
6. **授權範圍**（產業、地區、是否可轉售、是否含更新）

報價思路（自己填，非建議價）：

- 想法／顧問：工作坊 N 天 + 文件包  
- 源碼授權：一次費 + 年維護 %  
- 客製：人天 × 單價 + 模型／部署  

---

## 7. 演示腳本（最短）

1. 解鎖首頁 → 歷史榜遮罩  
2. 新增一則**虛構**八卦 → 出場確認  
3. 追問兩輪 → 到此為止  
4. 生成 → 指著建議分：「這是初估，我可改分改評語」  
5. 落盤 → 榜上分數變了  
6. （可選）後續一則：同一人觀感翻轉  

**禁止**用真實同事可識別細節做對外 demo。

## 9. 誠實邊界（對外別誇大）

- 現況是 **本機／工程原型級** 產品完整度，不是已上架大量用戶的消費 App。  
- 差異化在 **流程＋主觀分哲學＋校準**，不在「底模比別人強」。  
- 情感分析 **沒有**封閉多維數學公式；是 **可解釋的檢查清單 + LLM 整段理解 + 人終裁**（這點可當優點講：可調、可交接、可客製）。
